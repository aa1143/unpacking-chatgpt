# 拆开 ChatGPT 01：提问后发生了什么？

你有没有想过：

当你给 ChatGPT 发出一句话，点击“发送”以后，它的内部到底发生了什么？

它是不是先读懂你的问题，在“脑子”里想好一整段答案，然后再一个字一个字地告诉你？

其实不是。

ChatGPT 并不会先准备好一篇完整答案。它生成回答的核心方式，可以概括成一句话：

> 根据前面已经出现的内容，不断预测下一个 Token。

这句话看起来很简单，但 ChatGPT 从接收到文字，到真正生成回答，中间还要经过一整条计算链路。

这一期，我们先不碰复杂公式，用一个简单的例子，把这条链路完整走一遍。

---

## 从一句话开始

假设我们向 ChatGPT 输入：

> 猫最喜欢吃的食物是……

人类看到这句话，会自然联想到“鱼”“肉”或者“猫粮”。

但 ChatGPT 看到的并不是我们眼中的完整句子。对模型来说，这句话首先要被拆开、转换，再经过多层计算，最后才能生成后续内容。

整个过程大致可以分为五步：

```text
输入文字
   ↓
切成 Token
   ↓
转换成向量
   ↓
Transformer 处理上下文
   ↓
预测下一个 Token
   ↓
把新 Token 放回上下文，继续预测
```

下面逐步来看。

---

## 第一步：把文字切成 Token

计算机不能直接处理人类语言。我们输入的文字，需要先被切成一个个较小的片段。

这些片段叫作 **Token**。

为了方便理解，可以暂时把刚才那句话看成：

```text
[猫] [最喜欢] [吃的] [食物] [是] […]
```

不过，这只是一个便于理解的示意，并不代表 ChatGPT 一定会这样切分。

一个 Token 可能是一个字、一个词、一个标点，也可能只是一个词的一部分。不同模型使用的分词方式和词表也可能不同。

切分完成后，每个 Token 都会被转换成一个数字编号，也就是 Token ID。

模型真正接收到的，不再是肉眼可见的文字，而是一串数字。

但这里马上会出现一个问题：

数字编号只是编号，本身并不能表达含义。

就像身份证号码可以区分不同的人，却不能直接告诉你一个人的性格和爱好。

所以，还需要进入下一步。

---

## 第二步：把 Token 转换成向量

每个 Token ID 会被转换成一组可以参与计算的数字，这组数字通常被称为 **Embedding（嵌入向量）**。

你可以暂时把它理解成：

> 一个 Token 在模型内部的特征表示。

Token ID 主要负责区分“它是谁”，Embedding 则让模型能够在计算中表示和学习它的特征。

模型还需要知道 Token 出现的先后位置。

因为：

```text
猫喜欢吃鱼
```

和：

```text
鱼喜欢吃猫
```

使用的字非常接近，但顺序不同，意思却完全不同。

因此，模型在处理 Token 时，还需要加入位置信息。

完成这些转换以后，文字就变成了模型可以处理的数学表示，并被送入 ChatGPT 背后的核心结构——Transformer。

---

## 第三步：通过 Transformer 处理上下文

Transformer 是 GPT 系列模型的核心架构。

它要做的一件重要事情，是结合前面已经出现的 Token，计算不同信息之间的关系。

还是这句话：

> 猫最喜欢吃的食物是……

为了判断后面可能出现什么，模型需要综合“猫”“喜欢”“食物”等前文信息，而不是只看最后一个“是”。

这些信息会经过许多层 Transformer 模块不断计算和更新。

不同层会逐步形成更丰富的上下文表示。最终，模型会输出一个结果：词表中每个候选 Token，接下来出现的可能性分别有多大。

注意，到这一步为止，ChatGPT 仍然没有想好一整段答案。

它只是在计算：

> 下一个 Token 可能是什么？

---

## 第四步：选择下一个 Token

经过计算后，模型会得到一组候选结果。

为了便于理解，可以把它想象成一张概率表：

```text
鱼      ████████
肉      █████
猫粮    ████
其他    ██
```

这里只是示意，并不是某次真实运行产生的概率数据。

模型会根据这些结果和相应的生成策略，选择一个 Token。

它不一定永远选择概率最高的那一个。这也是为什么同一个问题问几次，ChatGPT 的表达可能不完全相同。

假设这一次生成了“鱼”，原来的上下文就变成了：

```text
猫最喜欢吃的食物是鱼……
```

但回答还没有结束。

---

## 第五步：把结果放回去，再预测一次

刚刚生成的“鱼”会被追加到已有内容中，成为新的上下文。

模型随后再次计算：

> 在“猫最喜欢吃的食物是鱼”后面，下一个 Token 应该是什么？

下一次可能生成“类”，于是内容变成：

```text
猫最喜欢吃的食物是鱼类……
```

模型再把“类”放回上下文，继续预测下一个 Token。

整个过程不断循环：

```text
预测一个 Token
      ↓
追加到上下文
      ↓
再次预测
      ↓
继续追加
```

直到模型生成结束标记，或者触发系统设定的长度限制，一段回答才算生成完毕。

所以，我们看到的完整答案，并不是 ChatGPT 一次性想好后再完整输出的。

它是一个 Token、一个 Token 逐步生成出来的。

---

## 为什么我们看到答案一点点出现？

平时使用 ChatGPT 时，我们经常看到文字不断出现在屏幕上。

这不只是一个模拟真人打字的动画。

模型本身就需要逐步生成 Token，应用再通过流式传输，把已经生成的内容持续展示给用户。因此，我们会看到答案一点点出现。

不过，“逐 Token 生成”也不严格等于“逐字生成”。

一个 Token 可能包含一个字、多个字，也可能只是某个词的一部分。界面最终如何刷新，还受到产品传输和渲染方式的影响。

---

## ChatGPT 只是在“文字接龙”吗？

看到这里，很多人可能会产生一个疑问：

如果 ChatGPT 只是在预测下一个 Token，那它是不是一个高级版的文字接龙工具？

从生成目标看，“预测下一个 Token”确实是它最核心的任务。

但不要低估这个任务。

为了准确预测下一个 Token，模型必须从海量数据中学习语言结构、概念之间的联系、常见事实、写作模式以及解决问题的规律。

当模型规模、数据规模和训练方法发展到一定程度后，仅仅为了把“下一个 Token”预测得更准确，模型就会表现出许多复杂能力。

至于这种能力能不能被称为真正的“理解”或“思考”，是另一个更大的问题。

至少从运行机制上看，我们可以确定：

> ChatGPT 并不是先在内部写好一篇完整答案，再把它逐字播放出来。

---

## 把整个过程重新串起来

现在，我们把一句话进入 ChatGPT 后的流程重新走一遍：

1. 用户输入文字。
2. 文字被切分成 Token，并转换成 Token ID。
3. Token ID 被转换成向量，同时加入位置信息。
4. 向量经过多层 Transformer，模型结合上下文进行计算。
5. 模型得到下一个 Token 的候选结果。
6. 选择一个 Token，把它追加到上下文中。
7. 重复计算，直到回答结束。

最后再浓缩成一句话：

> ChatGPT 根据前面已经出现的内容，不断预测下一个 Token，最终生成完整回答。

这就是你点击“发送”以后，ChatGPT 内部发生的基本过程。
